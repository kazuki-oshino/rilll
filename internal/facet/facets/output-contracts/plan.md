# Plan

このセクションは、エージェントが直前の作業で得た理解をもとに「これから何を / どの順で / どんな未解決事項を残しているか」をタスクリスト型で書き出すための構造化テンプレートである。

以下のルールを守ってこのテンプレートを埋めること:

- 見出し (`## Goals` / `## Steps` / `## Open Questions`) と順序は改変しない。
- 各見出し直下では、本テンプレートの説明文 (この `<...>` を含む行を含む) を削除し、実際の内容で置き換える。
- 各行は行頭マーカ (`- ` または `- [ ] ` / `- [x] `) で始め、1 件 1 行で簡潔に書く。
- 該当事項が無い見出しでは、その旨を 1 行だけ書く (例: `- なし`)。
- 推測ではなく、Phase 1 の自由作業で確認した事実のみを書く。確認できていない事項は `## Open Questions` に逃がす。

## Goals

このタスク / ワークフローで達成すべき結果を 1-5 件、最重要から順に列挙する。

- <達成すべき結果 1: 観察可能な完了条件 / 受け入れ条件で定義する>
- <達成すべき結果 2>

## Steps

Goals を実現するために実行する手順を、上から順に依存関係を保って列挙する。各ステップは命令形 1 行で「何を / どの対象に / 何のために」が分かる粒度で書き、状態マーカを付ける。

- `- [ ] <ステップ>` : 未着手
- `- [x] <ステップ>` : 完了
- `- [~] <ステップ>` : 進行中 (任意 / 必要に応じて)

例:

- [ ] <ステップ 1: 対象ファイル / 対象 module を含めた具体的アクション>
- [ ] <ステップ 2>

## Open Questions

着手前 / 着手中に解消すべき疑問、外部入力が必要な判断、トレードオフが残っている設計選択を列挙する。無ければ `- なし` の 1 行だけを書く。

- <疑問 1: 質問内容 / 想定される選択肢 / 影響範囲>
