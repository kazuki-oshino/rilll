# AI Antipattern Guard

[policy:ai-antipattern-guard]
実装方針を決める回答エージェントが、AI 特有のもっともらしい誤判断を避けるための共有判断基準。

## 原則

| 原則 | 基準 |
|------|------|
| 配線を疑う | 新しい field / option / facet / context は呼び出しチェーン末端まで渡ることを確認する |
| スコープを閉じる | assign 済 task の境界外、要求外機能、早すぎる抽象化を採択しない |
| Fail Fast | 必須値をフォールバックで黙って補わず、契約違反として扱う |
| 置き換え切る | リファクタ後の旧コード、孤立 export、不要な compatibility shim を残さない |
| 指摘を直す | レビュー指摘は対象コードを修正し、テストやドキュメント追加だけで済ませない |
| 既存パターンに合わせる | 命名、エラー処理、テスト、永続化、artifact 形式は既存実装を確認して揃える |

## 方針回答時の確認

実装エージェントの問い合わせに答える前に、次を確認する。

| 確認項目 | 危険な回答 | 推奨する回答 |
|----------|------------|--------------|
| 配線忘れ | 「このフィールドを追加してください」だけで呼び出し元・保存先・bridge 伝搬に触れない | 追加箇所と、値が末端まで届く確認範囲を明示する |
| スコープクリープ | 次 task、複数 task、別 phase、便利機能を一緒に進める | 現 task の完了条件に閉じ、境界外は親 workflow に任せる |
| フォールバック | `?? ""`、既定値、空 catch で成功扱いにする | 必須データ欠落はエラーまたは workflow abort の契約に寄せる |
| Legacy 対応 | 指示なしに旧値マッピング、deprecated wrapper、互換 shim を追加する | 現在の spec / API に合わせて置き換え、不要な旧経路は消す |
| デッドコード | 「将来使うかも」で未使用 helper / export / branch を残す | 使用箇所がないものは作らない。置換後の旧コードは削除する |
| 指摘ずれ | 指摘対象を直さず、検証テストや説明文だけを追加する | 指摘対象のコードを修正し、必要なら回帰テストを添える |

## 配線忘れ

新しい値を導入する方針を選ぶ場合、回答には少なくとも次の観点を含める。

- 値を生成する場所
- 値を保持する型または option
- 値を渡す呼び出し元と呼び出し先
- 値を観測するテストまたは artifact

「実装ファイルだけ直す」方針は、workflow / bridge / provider / facet / persistence のいずれかを跨ぐ変更では不十分。

## スコープクリープ

問い合わせの options が現 task の境界外作業を含む場合、その option は採択しない。

| パターン | 判定 |
|----------|------|
| 次 task も同時に実装する | REJECT |
| 複数 task をまとめて完了扱いにする | REJECT |
| 明示されていない後方互換や移行 shim を足す | REJECT |
| 単一用途のために汎用 interface / registry / plugin 機構を足す | REJECT |
| 現 task の完了条件に必要な最小の型・関数・テストを追加する | OK |

## フォールバック

必須値を黙って補う方針は選ばない。

| パターン | 判定 |
|----------|------|
| `options.value ?? defaultValue` で、全呼び出し元が value を渡していない | REJECT |
| `catch { return "" }` で失敗を空値にする | REJECT |
| ファイル不在・schema 不整合を成功扱いで進める | REJECT |
| optional と設計された設定値に明示的な既定値を使う | OK |
| 失敗を workflow の終端理由や wrapped error として返す | OK |

## 既存パターン確認

方針が既存設計と合っているか、次の一次情報を優先する。

- `requirements.md` / `design.md` / `tasks.md` の契約
- 既存 Go 型、helper、test fixture、artifact 出力
- 同種 workflow の実装とテスト

推測で API やファイル配置を決めず、既存パターンがある場合はそれに合わせる。
